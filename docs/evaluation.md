# Evaluation Plan

This document describes the evaluation approach for the academic prototype.

## Scope

Evaluation will focus on demonstrating pipeline integrity, not on claiming definitive production performance.

## Planned Evaluation Areas

- file validation and document type classification correctness
- OCR extraction quality on sample documents
- visual tampering analysis stability on synthetic examples
- cross-document inconsistency detection behavior
- explainable report completeness
- run-time behavior on CPU hardware

## Constraints

- no fabricated accuracy or F1 values
- any model evaluation must be performed only after a real model is trained or loaded
- metrics should be reported transparently and conservatively
- public datasets should remain outside the Git repository

## Completed Tampering Baseline Results

The trained AIForge-Doc-v1 feature baseline uses a frozen pretrained MobileNetV3-Small with 64x64 RGB ImageNet-normalized inputs and a LogisticRegression classifier (`authentic=0`, `forged=1`).

Validation split results:

- accuracy: 0.607692
- precision: 0.626812
- recall: 0.532308
- F1: 0.575707
- ROC-AUC: 0.682670

Official held-out TestingSet results:

- accuracy: 0.520936
- precision: 0.526074
- recall: 0.422414
- F1: 0.468579
- ROC-AUC: 0.517846

These are tampering-model baseline results only. They are not overall fraud-detection performance, production accuracy, or a calibrated risk probability. The official TestingSet was not used for tuning.

## Integration-Test Evidence

Synthetic salary/bank PDFs and matching or mismatching salary-credit fixtures verify software data flow only: upload, OCR, extraction, verification, fusion, reasoning, risk, and separate heuristic/model tampering evidence. They are not research evaluation data.

Known limitations include the relatively weak official test ROC-AUC of approximately 0.518, absence of a trained end-to-end fraud detector, heuristic risk scoring, no production calibration, and optional external LLM support. The deterministic fallback reasoning does not require an external provider.

## Phase 13 Feature-Learning Experiment

A controlled MobileNetV3-Small representation experiment used the existing deterministic 2,598/650 train/validation split only. Input was 96x96 RGB with ImageNet normalization. Early feature blocks were frozen and their activations cached once; the final three feature blocks and classification head were fine-tuned for two epochs with a fixed seed, class-weighted loss, mild existing document augmentation on train only, and validation-F1 checkpoint selection.

Validation: accuracy 0.675385, precision 0.690000, recall 0.636923, F1 0.662400, ROC-AUC 0.762149 (650 samples).

The selected checkpoint was evaluated once on the untouched official TestingSet: accuracy 0.501847, precision 0.502098, recall 0.442118, F1 0.470203, ROC-AUC 0.510476 (1,624 samples; TN 456, FP 356, FN 453, TP 359). It underperformed the original LogisticRegression test accuracy of 0.520936, so it is not promoted as the active detector. The original LogisticRegression artifact and its recorded results remain unchanged. These are tampering-model results, not overall fraud-detection performance.

The previous validation-selected HistGradientBoosting alternative scored validation accuracy 0.650769, F1 0.632091, and ROC-AUC 0.701387; its locked official test result was accuracy 0.493227, F1 0.447280, and ROC-AUC 0.502733. The original LogisticRegression official test remains accuracy 0.520936, F1 0.468579, and ROC-AUC 0.517846. The 96x96 fine-tune is not promoted because its test result does not improve the original. No held-out metric was used for selection or tuning.

For comparison, the original LogisticRegression official test metrics remain accuracy 0.520936, precision 0.526074, recall 0.422414, F1 0.468579, and ROC-AUC 0.517846. The previous validation-selected HistGradientBoosting result remains validation accuracy 0.650769, F1 0.632091, ROC-AUC 0.701387 and official test accuracy 0.493227, F1 0.447280, ROC-AUC 0.502733. The held-out test was not used to select or tune either model.

## Phase 13 Graph Prototype

The CPU PyTorch Geometric GCN uses 7 train, 2 validation, and 2 test hand-authored synthetic rule scenarios. Labels are generated by the existing deterministic cross-document verifier. The test split agreement was 0/2 (accuracy, macro F1, and macro precision/recall all 0.0; ROC-AUC not defined because its test labels do not contain all classes). The tiny sample is not a meaningful independent evaluation. These numbers describe agreement with the rule engine on the stated scenarios only, not fraud accuracy. GNN output is advisory and never overrides explicit verification results or directly increases risk.

## Risk Interpretation

Risk is a heuristic evidence score, not a probability. Explicit cross-document failures are counted once; PASS checks are preserved as supporting verification evidence but do not count as inconsistencies. Heuristic tampering evidence is retained and capped in aggregate; its visual findings are not proof of fraud. The trained visual output is informational/advisory (the model probability is uncalibrated), and graph rule-distillation evidence contributes zero direct risk points. A matching salary/bank software fixture with two weak texture observations yielded 0 failed rules, 0 cross-document inconsistencies, and a heuristic score of 16/LOW. The corresponding mismatch fixture (salary 35,000; bank credit 25,000) yielded one salary/credit FAIL and a score of 45/MODERATE. These are synthetic software integration cases, not research or fraud-performance measurements.
